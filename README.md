# 选调雷达 · 2027届｜政府公告优先版

本项目是一份可独立打开的静态网页和一个需要部署后才能运行的公告监测器。展示全国31个省级地区、7条已整理资料及报名条件、时间、笔试、来源链接、倒计时、收藏和日历导出功能。网站部署后每5分钟尝试读取更新后的站点数据；定时监测任务在 GitHub Actions 运行。

**本次来源要求：政府官网优先，吉林大学就业网仅作高校备用来源。** 无法找到符合要求的来源时，保留“暂无已核验资料”，不拿其他高校公告或培训机构/媒体转载填空。页面所列7条资料是2026年9月21日整理的快照，不是持续联网核验后的实时数据。须以招录机关最终公告、附件、岗位表及后续更正为准。

## 来源政策与当前覆盖

- **首选**：省级党委组织部门、政府、人社/人事考试机构等 `*.gov.cn` 公告，须打开原文及附件人工核验。已配置的直接来源：北京、湖南、甘肃（3条）。
- **仅有的高校备用**：吉林大学就业网 `jdjywpt.jlu.edu.cn`、`jdjyw.jlu.edu.cn`。已配置的直接来源：上海、湖北、四川、贵州（4条），外加吉林大学选调信息索引（1个）。因此当前监控来源共 **8个**。
- **不采纳**：其他高校（例如原型使用过的华东师范大学、山东大学和南开大学）公告与索引，培训机构及媒体转载。这些旧来源已从 `data.json` 和 `sources.json` 的公开、监控入口移除。
- 其中湖北、四川的记录现已改为**面向吉林大学的版本**，绝不将其他高校的专属条件或校内时间混用。上海是适用于公告高校名单的选调信息，吉林大学是备用转载入口，并不是发布主体。
- 自动地区搜索仅接受 `*.gov.cn` 与上述两个吉林大学域名的搜索结果；同一次搜索若找到政府链接，会舍弃吉林大学候选。若该地区正式资料已有政府公告，也不会再添加吉林大学搜索候选。但搜索结果**不是核验**，发现线索绝不自动填入正式时间表。

部分招录机关把公告只放在独立报名系统或 PDF/附件中，本工具当前的自动搜索可能无法发现这些来源；对于未完成验证的独立报名系统，不会擅自宣称已经配置监控。31个地区表示**导航和搜索地区范围**，不是31个政府部门的直连监控已全部完成。吉林大学备用转载有时只适用于该校，不能推广到其他大学。

## 预览

解压后双击 `index.html`。本地打开 HTML 依靠内嵌快照即可显示7条资料；浏览器可能阻止 `file://` 读取 JSON，此时不会后台抓取新公告。若过去曾用“导入更新 JSON”加载旧数据，浏览器会优先保留导入内容；点击网页里的“恢复网站数据”可以回到新的公开快照。

## 部署 GitHub Pages 与自动监测

1. 在 GitHub 创建一个仓库，把本项目根目录的所有文件（包括隐藏的 `.github/`）上传到 `main` 分支。
2. 在 `Settings → Pages → Build and deployment → Source` 中选择 **GitHub Actions**。检查 `Actions` 是否已启用；如果自动提交监测结果被权限拦截，在 `Settings → Actions → General → Workflow permissions` 里允许合适的写入权限。若需要 Issue 提醒还须启用仓库 Issues。
3. 打开 `Actions → Monitor announcements and publish site → Run workflow` 运行一次。查看运行日志和 `monitor_status.json`；网络请求成功率不等于公告覆盖率。
4. 访问 Pages 的正式部署网址；准确地址请以 Pages 设置或部署结果为准。后续每天北京时间 **02:17、08:17、14:17、20:17** 计划运行，GitHub 不保证准点执行或仓库始终保持计划任务活跃。

工作流：检测7个既有文章和1个吉林大学索引的变化 → 对31个地区查询第三方搜索 RSS（政府官网/JLU 仅作候选）→ 写入待核验 `review_queue.json` → 如有新增候选，尝试创建 GitHub Issue → 发布静态站点。第一次直连检查只建立文章对比基线；目录第一次扫描只建立旧链接基线，RSS 发现的尚未收录链接可进入候选。失败记录在 `monitor_status.json`，**不能当成“没有公告”**。

## 如何人工更新正式信息

`data.json` 是唯一正式发布资料；`monitor.py` **不会自动修改它**。

1. 打开 `review_queue.json` / GitHub Issue，优先找到组织部门的官方公告和附件。只有无法找到官方原文且吉林大学发布了相应公告时才使用吉林大学作为备选；其余网站只可用于帮助寻找政府公告，不可进入正式资料或自动候选队列。
2. 确认届别、发文主体、公告适用学校、岗位类别、专业限制、年龄、推荐流程、报名起止的**具体时刻**、不同层级岗位截止时间、笔试和校内截止时间。高校专属公告必须在标题和资格摘要中明确“面向吉林大学”，不可扩大适用范围。
3. 人工编辑 `data.json.records`。字段 `source` 必须是合法 HTTPS 政府网址或以上两个吉林大学就业网域名；政府来源使用 `sourceTier: "government"`、`sourceType: "官方"`，吉林大学来源使用 `sourceTier: "jlu_fallback"`、`sourceType: "吉林大学备用"`。缺少具体时刻时在说明中写清，不能以零点冒充公布的真实时刻；岗位差异用 `deadlines` 分开记录。
4. 完成审核后把相应候选 `status` 设为 `reviewed`（不相关设为 `dismissed`），更新 `asOf` 和核验日期，再执行：

```bash
python -m pip install -r requirements.txt
python build.py
python build.py --check
python -m unittest discover -s tests -v
```

将修改提交到 `main` 后工作流将部署更新版本。用户在浏览器自行导入的旧 JSON 会覆盖公开资料，需点“恢复网站数据”。不要在仓库或 Issues 上传考生个人信息。

## 单机检查与文件说明

```bash
python monitor.py               # 联网检查；仅产生待核验线索
python monitor.py --skip-discovery  # 只检查已配置的8个来源
```

程序仅请求公开 HTTPS 页面，不绕过登录、验证码、访问限制，拒绝访问或内容解析失败就记录错误；不会访问第三方搜索发现的候选 URL，不收集个人资料。`sources.json` 管理来源，`source_policy.py` 定义政府/JLU 白名单，`monitor.py` 执行监测，`watch_state.json` 去重，`review_queue.json` 保存待核验候选，`monitor_status.json` 保存检查状态；`build.py` 负责检查正式来源政策与更新内置快照，`tests/` 是离线回归测试。`monitor.py --fixture-dir <目录>` 的模拟输入需提供 `monitor-0.html` 至 `monitor-7.html`，开启地区搜索时还需 `search-0.xml` 至 `search-30.xml`。
